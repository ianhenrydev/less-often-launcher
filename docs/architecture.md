# Implementation notes

`BucketPolicy`, `Sessions`, `Quotes` and `DisplayJournal` are independent testable policy classes. Android adapters provide a boot-count discriminator, `SystemClock.elapsedRealtime()`, app-private synchronous durable commits, and secure-setting access. Events, overlay callbacks, commits and display mutations are serialized on the Android main looper. Each write touches only its own keys.

`AppCatalog` uses `LauncherApps` for current-user launchable activities, installed labels, component availability and package callbacks. The manifest declares launcher-intent package visibility rather than requesting unrestricted package queries. Source mapping remains authoritative. Work profiles and other users are outside the specified personal-phone scope.

`MainActivity` uses Compose for Home and the two lists. `SetupActivity` keeps operational status and recovery controls separate. `GateView` uses native views where focusable accessibility-overlay/IME behavior matters. An exported Home/setup surface accepts no target, bucket, quote or grant extras. The accessibility service is exported only behind Android's signature-level bind permission. The boot receiver is not exported. There are no session-grant receivers, configuration deep links, shared-storage configuration readers or content providers.

`GateService` retrieves interactive windows and reads only root package names and window metadata. It excludes its own accessibility overlay and IME from underlying application identity. Focused system interruptions, keyguard/screen-off, Home, Back/cancel, and actual application switches discard attempts. Platform infrastructure without a normal launchable entry is not automatically treated as a new Restricted package. Explicitly configured packages still obey policy. Home delivery explicitly cancels a prelaunch challenge even when Home was already underneath it.

A locked foreground package receives an opaque, focusable, touch-blocking `TYPE_ACCESSIBILITY_OVERLAY`. System navigation remains available. Launcher-initiated attempts remember a validated component but do not launch it until the durable grant succeeds. External attempts remember the package only and remove their overlay on success, leaving the existing notification/link/Recents destination intact. This architectural property still needs verification on the actual Pixel; there is no claim of intercepting a launch before it occurs.

A dedicated main-handler callback checks a foreground deadline. A 500 ms reconciliation pass also checks window state and capability changes; screen wake/unlock events reconcile elapsed deadlines after sleep. `Handler` uses uptime internally, so wake reconciliation is necessary: the persisted source of truth is always elapsed realtime, never the handler delay or wall time. Background expiry never starts a gate over unrelated foreground apps. Boot-count mismatch, missing identity, malformed state, expired deadlines and implausibly distant deadlines remain locked. Reading/reopening does not write a grant or extend a deadline.

The display journal captures both baseline keys and existence before applying either setting. Each write intent is journaled before the secure-setting mutation, allowing partial-write recovery. Duplicate events avoid writes; transitions between Restricted packages retain baseline ownership. The journal detects concurrent changes and refuses ambiguous restoration. A process crash/force-stop cannot promise cleanup; the ADB recovery script handles that case with exact recorded values.

`DisplayContinuity` preserves an already-owned grayscale transform through up to 1,000 ms of inconclusive window metadata, such as an absent activity root or an inactive Home window briefly exposed behind an activity transition. Repeated uncertain events do not extend that deadline. A positively focused/active permitted app, explicit Home delivery, screen lock/off, or service teardown restores immediately. A dedicated callback reconciles a gap at its deadline; persistent window loss still raises the existing health error. A pending display journal seeds this short recovery grace on process reconnect. This continuity state never grants access, infers a session, or changes any session deadline.

Accessibility `onInterrupt()` triggers reconciliation rather than unconditional display restoration: Android defines it as [interrupting accessibility feedback](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#onInterrupt()), which is not evidence that the foreground application changed. Actual window/system interruptions continue to cancel a challenge through foreground reconciliation.

The launcher never requests notification access, suspends packages, reissues notifications or collects screen content. No Internet permission, analytics or telemetry is present. Debug instrumentation and the separate `probe` APK are development tools and are not shipped as launcher entry/grant APIs.
