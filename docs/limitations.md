# Current limitations

Version 0.2.0 was accepted for personal use on November 6, 2026 after the user confirmed more than a week of daily testing. This acceptance does not certify other devices. [Validation history](validation.md) distinguishes passed, partial and unverified checks.

- **Device support:** minimum API 37; tested only on Pixel 6a / API 37. Pixel 11, other manufacturers and later APIs have no device validation yet. Accessibility, keyboard, gestures and display behavior need checks on each phone.
- **Installation/distribution:** computer-assisted sideload and secure-settings grant required. No Play Store workflow, release signing or automatic updater is configured. The setup/recovery helpers target Windows; device regression automation remains Pixel 6a-specific.
- **Personal app policy:** bundled groups reflect the original author's apps, including personal service/provider choices. Unknown apps default to Restricted. No runtime group editor, onboarding policy picker or configurable session duration. Review the source policy before publication and before use on another phone.
- **Enforcement:** personal friction, not parental controls, kiosk software or a security boundary. Disabling accessibility, force-stop, changing launchers or uninstalling can bypass it. External apps appear before detection, so brief content exposure can occur. Notifications, previews and inline replies remain native. Embedded content in permitted apps is not filtered; restrictions are package-wide.
- **Display:** grayscale affects the whole display, including the keyboard and system UI. Crashes/force-stop can leave it active. Exact recovery requires the journal or that phone's saved baseline. Concurrent color-setting changes can pause automatic restoration; bedtime, Night Light and other display interactions need more testing.
- **Scope:** split-screen, picture-in-picture, work profiles and other Android users are outside the supported scope. TalkBack-specific acceptance is not part of the current validation; general accessibility compatibility is not certified.
- **Usage awareness:** optional and local. Screen time means interactive, unlocked time and can differ from Digital Wellbeing. Permission gaps, service disconnects, retained-event limits, reboot and clock/time-zone changes can yield partial totals. Notifications already present on listener connection are baselined rather than counted as new. Notification updates do not count again while the same instance remains active.
- **History/comparison:** seven-day history; comparisons require at least three eligible prior days with checkpoints through a common time. Daily use of 0.2 is user-confirmed. Separate instrumented evidence for a naturally accumulated comparison baseline, repeated real clock/time-zone changes and notifications making the screen fully interactive is not recorded.
- **Persistence:** local state is not backed up or transferred. Uninstall/clear-data loses sessions, statistics and recovery journals. An in-progress quote is discarded. Keyboard-generated plain text remains an accepted input boundary despite paste suppression.

See [acceptance.md](acceptance.md) for remaining scenarios, including reboot, background/sleep expiry and conflicting display settings. Do not infer a pass from implementation or unit tests alone.
